## Рабочие срезы

### 1. Полный профиль на существующей авторизации

Сначала один рабочий путь: открыть профиль → изменить имя/optional phone/организацию → сохранить → открыть форму нового мероприятия → увидеть актуальные контактные данные → перезапустить и снова войти, профиль сохранён.

- Минимальный ProfileRepository/current profile model, observe/read/save через текущую подтверждённую сессию. Email/id/emailVerified не редактируются. Имя Unicode, без требования двух слов; телефон optional в российском формате, организация optional. Политики централизовать и переиспользовать, не размножать несовместимые regex.
- Имя уже существует в `AuthData.names`: выбрать один источник истины, сохранить signup-имена при миграции, не создать вторую расходящуюся карту. Account identity/сессия и изменяемый профиль разделены настолько, насколько нужно: сохранение имени не должно вызывать ложный logout/смену личности из-за equality guard.
- Profile VM принадлежит прежнему root/entry owner, состояние формы/dirty/busy/error определено явно. Во время save один запрос; устаревший result/finally после logout/hidden/new operation не меняет новую форму. Вернувшийся observer не затирает несохранённое редактирование. На Back из dirty формы дать сохранение/отброс по принятому проектному паттерну.
- Разумный demo default: несохранённые поля не persist в серверном snapshot, после нового процесса читается последняя сохранённая версия; не обещать автосохранение. Saved-state хранения PII сверх принятой потребности не добавлять.
- Сохранение меняет профиль и подстановку **новых** заявок. Уже выданные билеты, имя/телефон/ответы регистрации и исторические check-ins не переписывать. Организация профиля не становится автоматически ответом на произвольный вопрос «Вуз / факультет»; это разные сущности.
- Copy user ID через platform/clipboard, без секретов; logout использует существующий AuthRepository и очистку private owners. Все profile reads/writes проверяют actor/current generation, отказ записи не публикует ложное сохранение.
- Настройку email notifications сохранять явно вместе с профилем. Demo default: выключает необязательные напоминания, но не confirm/reset/выдачу билета и явно запрошенный resend. Точное backend-поведение ещё согласуется, UI не должен обещать отключение обязательных писем.

### 2. Persistence и совместимость

- Новые profile fields сохраняются в том же полном snapshot на IO под общим Mutex. Если необходима schema 5, сделать migration v1–v4→новая без потери accounts/password proofs/challenges/names/events/drafts/covers/answers/tickets/grants/manual credentials/check-ins. Номер схемы сверить перед изменением.
- Значения для старых записей: сохранённое имя, phone/organization отсутствуют, notification default явно описан. Не придумывать профиль из случайной чужой регистрации. Каждый writer (auth/editor/ticket/grants/check-in/attendance/profile) сохраняет новые поля и прежние данные.
- Corrupt/unsupported snapshot не затирать seed; downgrade не обещать. Сессии/raw secrets/outbox/UI guest cache по-прежнему не делать persistent лишь ради миграции профиля. Новая сборка с повышенной схемой не должна автоматически сбрасывать пользовательское demo.

### 3. Настоящие PDF и XLSX за портами

- Минимальный Documents port/use case готовит авторизованный snapshot данных и file descriptor/handle; platform adapter отвечает за генерацию/чтение/сохранение bytes. Pure domain не зависит от Android Context/Uri/PdfDocument; data:fake не получает Android runtime. Не тащить fake state/DTO непосредственно в Compose/генератор.
- **PDF собственного текущего ACTIVE билета:** название/дата/zone/место, имя участника/displayNumber, тот же QR и manualCode. Никакого нового credential/регистрации при экспорте. История без QR; чужой ticket ID недоступен. Доступ/актуальность проверяются перед подготовкой и перед передачей результата пользователю; отмена/logout в ходе операции не выдаёт поздний файл старой личности.
- PDF должен реально открываться как PDF, поддерживать кириллицу, читаемые даты, длинные названия и QR с quiet zone. Не переименовывать HTML/PNG в .pdf. Проверить независимым чтением/рендером реального артефакта; визуальную проверку QR отделить от настоящего scan.
- **XLSX владельца E:** все регистрации E из одного snapshot, включая Cancelled, со статусами и ответами анкеты, независимо от dashboard q/page. Не строить экспорт из видимого списка или многократно загружаемых меняющихся страниц. SnapshotAt/данные E сохранить в файле.
- Минимальные колонки: registrationId/displayNumber, имя/email/phone, время регистрации, статус, первый check-in time/checker при наличии, formVersion, ответы по stable questionId/title. Для существующего demo registration timestamp — consentAcceptedAt с явным описанием, не выдуманное поле истории. Checkbox boolean, single-choice — label и стабильный optionId, отсутствие ответа пустое, legacy Used без record — пустые время/checker. QR/manual codes в XLSX не включать.
- Все пользовательские строки XLSX записывать как текстовые cells, не формулы (`=`, `+`, `-`, `@` в исходном ответе не должны исполняться). Реальный OOXML ZIP/workbook, правильные MIME/расширение. Не CSV с именем .xlsx, не статическая fixture вместо фактических участников. Проверить независимым reader содержимое/число строк/ответы/типы cells.
- Перед добавлением библиотеки проверить текущие зависимости и официальную Android-совместимость/лицензию. Не подключать тяжёлый desktop runtime без проверки. Генерация на IO, bounded memory/streaming где уместно; cancellation закрывает ресурсы и удаляет принадлежащие операции незавершённые temp files.
- Сохранение через системный SAF CreateDocument/content resolver, правильный MIME/name, обработка отмены picker, отсутствующего provider, ошибки записи/закрытия. «Сохранено» только после успешного завершения записи. Без broad storage permissions/непроверенного произвольного пути. При добавлении Share — FileProvider/content URI с временным read grant, без file://.
- Временные файлы private, ограниченный lifetime/cleanup на исходах/logout/startup, без включения в backup и логов PII. Файл, который человек уже явно сохранил/передал, не обещать отозвать. Поздний picker/result старого аккаунта не экспортирует данные новой/старой личности.
- Можно реализовать прямой suspend export для demo; не нужно строить полный HTTP DocumentJob scheduler до появления API. Экран должен зависеть от порта, а не места генерации: будущий remote сможет скачать серверный документ.

### 4. Повтор писем — честный demo

- Добавить resend собственного билета через port с текущей проверкой доступа/статуса, typed result/error и явным retry/cooldown. Получатель берётся из сохранённой регистрации/подтверждённой сессии; не принимать произвольный email из UI и не давать анонимный lookup по ticketId.
- Использовать существующий общий fake outbox, не новую несвязанную очередь. Это только имитация серверной отправки: показать «Demo: письмо добавлено в outbox» или принятый эквивалент, не «доставлено на реальный email». Никаких реальных SMTP/внешних рассылок.
- Повтор не создаёт регистрацию/ticket, не меняет QR/места/статус. Failure не уничтожает билет. Busy защищает двойной tap; Retry повторяет ту же осмысленную команду, без автоматической очереди при восстановлении сети.
- Cooldown задаётся централизованным fake policy/Clock и возвращаемым retryAt, без отдельного захардкоженного UI-таймера. Время auth и времени событий не смешивать. После logout старые ошибки/получатели/таймеры не остаются новому аккаунту.
- Гостевой receipt продолжает жить в текущем flow, не обретает постоянный кабинет, новое серверное разрешение или автосоздание аккаунта. Не расширять этот этап незаданным guest download/recovery протоколом.
