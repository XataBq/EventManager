## Что реализовать

### 1. Тема и токены

В `core:designsystem` оформи единые semantic colors, typography, shapes и повторяющиеся размеры/отступы из блока 06. Используй Material 3 primitives, сохраняя собственные EventPass-цвета, включая success/warning/danger/muted. Не размножай одинаковые hex и размеры по компонентам.

Тема MVP тёмная, dynamic color выключен. Локально включи Inter с весами 400/500/600/700 и файлом лицензии из проверенного источника; не загружай шрифт во время запуска приложения. Не обновляй зафиксированные версии стека ради T03 без конкретной несовместимости.

### 2. Базовые переиспользуемые компоненты

- Primary/secondary/danger/text actions: enabled, disabled, loading; основные и компактные варианты там, где есть образец.
- Поля ввода, пароль с переключением видимости и поиск: label, placeholder, значение, focus, error/supporting text, disabled; подходящие keyboard/IME параметры.
- Consent checkbox, settings switch, option card/single choice и segmented tabs со счётчиками.
- Status badge/dot/result mark, avatar с инициалами, key-value row, metric card, общий контейнер секции/карточки.
- Empty/error/inline-error states и диалог подтверждения с обычным/destructive действием.
- Верхняя панель: guest/auth/nested визуальные варианты; нижняя — ровно «Билеты · Мероприятия · Профиль» с иконками из установленного дизайна.

API компонентов — параметры состояния и callbacks. Design system не зависит от domain repositories, fake, Hilt, NavController или конкретной бизнес-роли. Не добавляй обязательный BaseViewModel/use case для галереи. Называние и разбиение файлов выбирай по существующим соглашениям; не создавай универсальную карточку с десятками флагов.

EventCard/TicketCard/ParticipantRow можно показать как представительные композиции базовых элементов в галерее. Не превращай это в реализацию настоящих экранов мероприятий, билетов, профиля или дашборда. Рабочая генерация QR, камера, разрешения и guest saved state относятся к следующим этапам; декоративный QR из Figma не выдавать за работающий билет.

### 3. Галерея для H1 и интеграция оболочки

Сделай доступную из demo-приложения галерею: группы компонентов, их состояния и несколько длинных/пустых примеров. Checkbox/switch, ввод, видимость пароля, выбор варианта и tabs должны переключаться; loading/disabled/error должны быть воспроизводимыми. Предоставь ясный способ открыть галерею из установленного APK.

Галерея — demo/debug surface. Не добавляй четвёртый продуктовый таб. Обнови текущие top/bottom bars общими компонентами там, где это входит в T03; сохрани существующий demo-экран и его проверяемое поведение. Не меняй права, email-сопоставление, ошибки и остальные правила T02.

Проверь при интеграции, что нет двойных system/IME insets, потери entry owners скрытых вкладок, сброса счётчика или накопления дублей. Изменять app navigation разрешено лишь в объёме входа в галерею и её корректного Back/закрытия; не переделывать механизм сохранения стеков без выявленной необходимости.

### 4. Android и доступность

Ориентир ширины — 390 из Figma, адаптация для телефонов 360–412dp. Геометрию переводить в dp/sp, а не масштабировать весь макет как изображение. Фиксированная высота длинного Figma-frame не является высотой устройства.

Сохрани visual heights 44/36 и radius 8 там, где это задано, но touch areas — не менее 48dp без перекрытий. Поля/кнопки должны допускать рост текста. System bars и клавиатура не перекрывают действия. Для иконок действий нужны описания, для selected/checked/error — корректная semantics; статус обозначается текстом, а не только цветом.

Иконки используй как векторные ресурсы/проверенные assets, с фиксацией источника/лицензии при необходимости. Не заменяй их emoji или буквенными заглушками. Русские UI-тексты — Android string resources, пользовательские примеры — параметры композиции.
