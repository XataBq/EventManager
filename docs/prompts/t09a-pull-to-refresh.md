## Матрица обновляемых данных

Перед изменением составь короткую карту **поверхность → entry/VM → resource ID → команда чтения → indicator state**; сверь её с фактическим кодом. Не ограничиваться поиском текста на кнопках: проверь общие оболочки, состояния ошибки и вложенные scroll containers.

| Поверхность | Что делает жест | Что сохраняет / особые условия |
|---|---|---|
| Билеты: текущие/история | Читает собственные tickets/events через прежний TicketRepository.refreshMyTickets | Сегмент, выбранный ticketId и навигационный родитель; если выбранный билет изменился, применить текущую политику статуса/QR. Не обновлять вместо них MyEvents |

| Мои мероприятия: Организую/Волонтёр/Черновики | Читает данные MyEvents для текущего пользователя | Текущий сегмент/позицию по возможности. Сейчас порт возвращает общую коллекцию трёх сегментов: один такой read допустим; не добавлять три параллельных запроса и не переключать сегмент |

| Волонтёры E | Обновляет read/list grants **того же E** | Сохранить ввод поиска/target, не выполнять grant/revoke. Обновление общего store может закономерно изменить наблюдаемые данные связанных экранов. Это допустимо. Запрещены **чужие/скрытые refresh-команды**, смена выбранного ресурса, утечка результатов между entry и отображение spinner не на том экране. Не создавать независимые копии store ради изоляции UI.

## Где жест не запускает общую загрузку

- Не ставить перехватчик на Activity, весь AppHost/PrivateShell или поверх всех табов. Gesture wrapper принадлежит конкретной видимой Route/Screen/entry и её scrollable content. На вложенном Dashboard/Volunteers/Event жест не доходит до root MyEvents/Tickets под ним.
- Login/signup/confirm/reset — формы команд, не источники обновляемого списка. Сканер/камера/результат прохода — отдельная state machine; потянуть preview не означает повторить check-in/refresh другого экрана. Сохранить существующие access-check и явные next/retry действий.
- Editor черновика/события и publication result не должны терять несохранённое редактирование или повторять save/publish через жест. У них нет обычной кнопки «Обновить» в нормальном состоянии — не добавлять разрушительный reload для формального единообразия.
- Гостевой QR receipt — выданный snapshot текущего flow, не разрешение повторно загрузить ticket по ID/email. Жест не создаёт заявку/письмо, не стирает и не заменяет receipt. Не добавлять persistent guest cache. Для receipt без отдельного безопасного read жест отключён; underlying Event не получает его.
- Fullscreen QR, confirmation/error dialog, системный picker/SAF, внешнее окно и скрытая entry не передают pull в нижележащую поверхность. Не ломать сохранение pending export при configuration change.

## UX и состояние

1. Удалить обычные видимые кнопки/ссылки/icon actions «Обновить» со **всех продуктовых поверхностей**, где они дублируют чтение данных. В момент постановки это TicketsScreen, MyEventsScreen, EventScreen и DashboardScreen; проверь весь проект заново. Не оставить прежний `dashboard-refresh` как невидимый костыль для тестов.
2. «Повторить» при ошибке, повтор mutation в Dialog, resend письма, «Следующий билет», «Загрузить ещё» — разные действия; они остаются адресными. Не превращать pull в повтор отмены/grant/submit/resend/export. При ошибке чтения возможны и pull, и доступный явный retry по принятому UI.
3. Жест активируется сверху при scroll offset=0, после достаточного расстояния; обычный scroll вверх/вниз, горизонтальный свайп сегментов, выделение текста/ввод и drag внутри другого элемента не запускают его. У short/empty/error content есть scroll/gesture target: обновление работает даже без полного экрана строк.
4. Индикатор по центру сверху внутри доступных insets; не перекрывает кнопки/системную панель, не сдвигает случайно соседний таб. Учитывать вложенную прокрутку и Scaffold/IME, не добавлять второй независимый verticalScroll/LazyColumn вокруг существующего без необходимости.
5. Начальная загрузка и ручной refreshing — отдельные состояния. При refresh оставлять прежние данные и позицию, показывать только indicator; Network/Timeout/Storage не очищают разрешённые данные, индикатор завершается и доступен повтор. Loading не имитировать фиксированным delay. Доступ/сессия утрачены — очистить PII по прежней политике.
6. Повторные pulls во время ongoing refresh не создают очередь/шторм: один пользовательский refresh на текущий owner/resource. Начальный/lifecycle/ручной refresh должны согласовываться. Не ломать внутренний follow-up dashboard при stale page: он обеспечивает актуальную revision и отличается от повторного жеста пользователя.
7. Stop/hidden/Back/logout/смена eventId/аккаунта отменяют либо инвалидируют старое чтение. Поздний ответ/finally A не меняет данные, ошибку или refreshing новой entry B. Новый observer результат B не откатывается старым refresh A; сохранить регрессии `aaca508`. Фиксированный demo Clock не является порядком новизны.
8. На повороте/new process transient refresh не восстанавливается бесконечным spinner. Автоматическое актуальное чтение — по текущему lifecycle; gesture state не persist как бизнес-команда. Старые ответы/секреты не складывать в SavedStateHandle.
9. Для TalkBack/пользователей без жеста предусмотреть доступное semantic action «Обновить данные» на нужном контейнере и объявление состояния обновления. Не возвращать обычную видимую кнопку «Обновить» ради accessibility. Error retry остаётся доступным. Проверить в реальном accessibility UI в рамках адресной приёмки, наличие semantics само по себе не доказательство TalkBack-прогона.

## Минимальная архитектура

Route связывает конкретный onRefresh с VM своего владельца; Screen получает callback/state, design system рисует gesture/indicator. VM различает request generation/resource и состояние чтения; repository остаётся источником данных/прав. Не вызывать repository из shared composable, не передавать глобальный selectedTab в качестве адреса чтения, не использовать event bus «обновить всё».

Применять общий компонент сначала на одном полном срезе (например Dashboard), доказать nested scroll/current entry и затем перенести на остальные поверхности. Отдельно проверить Tickets/MyEvents/Event: их старые lifecycle refresh используют STARTED и живут в нескольких сохраняемых стеках; убедиться, что реально скрытая запись не инициирует ненужные чтения и не перехватывает жест. При добавлении refresh в Volunteers/Profile не очищать input через start()/bind() всей формы.
