- Развивай существующую Navigation 3, не мигрируй на Navigation 2 и не строй параллельное приложение. Сохрани per-tab stacks, entry ownership и уничтожение ViewModel при удалении записи.

- Успешный обычный Login открывает Tickets. Если есть допустимое назначение — возвращает туда: EventDetails(eventId) или исходный защищённый раздел (например MyEvents). Не доверяй произвольному returnUrl и параметру role.

- Полный EventDetails/регистрационная форма и Tickets — T05. Для проверки возврата используй небольшой явный экран-приёмник eventId без бизнес-формы либо независимый тест маршрута; не рисуй фиктивный успех регистрации. Корневые Tickets/MyEvents остаются честными временными поверхностями, а не объявляются готовыми продуктовыми экранами.

- Unauthenticated ведёт во вход с безопасным назначением; Forbidden не запускает циклический Login и убирает недоступный маршрут с понятным сообщением. Права на мероприятие — по eventId, общей политикой; существующих capabilities достаточно, не добавляй глобальный User.role или будущие scanner/dashboard экраны.

## Проверки

Сначала докажи небольшой срез signIn → session → shell, затем остальные auth-шаги. Тестируй наблюдаемое поведение, не каждый getter и не цвета.

| Проверка | Ожидаемый результат |
|---|---|
| SignUp → confirm → signIn | Нет сессии до ручного Login; повторная почта/неверный пароль/неподтверждённый email различимы |
| Guest ticket → отдельный аккаунт на тот же email | После подтверждения и входа репозиторий выдаёт его билеты; другой email — нет; signup не создаёт/не отправляет заявку |
| Reset по коду | Неверный/истёкший/использованный код отклонён; cooldown работает; новый пароль принят только после успешной проверки; старый пароль перестаёт подходить |
| Отказ/timeout и двойное нажатие | Нет ложного успеха, повторной мутации или автоматического retry; CancellationException не превращается в сетевую ошибку |
| Возврат после auth | Только разрешённое назначение; ответы анкеты не хранятся/не отправляются; повтор результата не дублирует маршрут |
| Logout/expiry/смена аккаунта | Очищены все приватные стеки; Back/tab/recreation не возвращают прежние данные; поздний ответ старой операции игнорируется |
| Cold/warm confirmation link | Разрешённый путь обработан один раз; подтверждение без сессии; неверный/истёкший link не открывает кабинет |
| Восстановление | Email/безопасное назначение восстанавливаются по выбранной политике; пароль/коды не сохраняются; неизвестная сессия не показывает приватный UI |

Auth/fake/навигацию покрой unit/contract tests. Где для ViewModel нужны управляемые корутины, используй уже выбранный стек и минимальную тестовую зависимость с совместимостью, проверенной по первичным источникам. Не обновляй весь toolchain ради T04.

Из-за изменения стартового экрана, NavEntry ownership и guards добавь/обнови узкий instrumentation smoke: guest startup → явный login → shell → logout → Back; restoration не обходит session guard. Для риска холодной ссылки используй адресную проверку доставки в Activity. Не строй полное автоматическое прокликивание всех экранов; визуальную приёмку выполняет человек. Существующие entry/navigation/insets проверки должны продолжить проверять свой сценарий, а не стать no-op.
