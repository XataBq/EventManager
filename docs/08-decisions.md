# Решения и открытые вопросы

**Обновление 2026-10-27:** [ответы B01–B08](12-backend-answers-2026-10-27.md) заменяют соответствующие решения от 21 октября. Гостевой QR доступен сразу и пока сохранён экран/flow через saved instance state; после закрытия — письмо/кабинет. Без автосоздания аккаунта и сохранения анкеты перед входом; телефон optional, регистрация закрыта после начала события.

Дата исходного исследования и ответов пользователя: 2026-10-21. Статусы: **задано** — запрос пользователя/явный источник; **принято для MVP** — пользователь подтвердил; **временно принято** — можно разрабатывать на стабах, затем сверить с API; **предложено/открыто** — ответа ещё нет. Продуктовое решение пользователя не означает согласование серверного контракта с backend-разработчиком.

## Продуктовые вопросы

Пользователь подтвердил начало работы без готового API при сохранении возможности менять правила централизованно. Ответы H0 ниже зафиксированы; Q04/Q08 дополнительно разъяснены и подтверждены. Не требовать повторного подтверждения уже принятых вариантов. Готовый API не является условием старта T01–T03; серверные уточнения остаются отдельным треком.

| ID | Вопрос | Решение и ограничения | Статус |
|---|---|---|---|
| Q01 | Телефон и имя | Телефон optional; если заполнен — российский номер. Политика Required/Optional/Hidden остаётся централизованной и обратимой. Имя на любом языке, без ограничения кириллицей/латиницей и требования двух слов | B06, принято 27 октября; заменяет прежнее required |
| Q02 | Пересечение связей на одном мероприятии | Независимые owner/grant/registration, включая одно E. Билет не выдаётся автоматически владельцу/волонтёру. Сервер проверяет права каждого закрытого действия; отзыв grant не отменяет билет | B01, подход принят 27 октября; формат capabilities до API |
| Q03 | Вход со страницы события | Только возврат на E, без сохранения ответов и автоматического завершения заявки; форму заполняют заново | B04, принято 27 октября; CompleteRegistration исключён |
| Q04 | Гостевой билет | Аккаунт не создаётся. QR возвращается приложению сразу; компактные данные в SavedStateHandle/onSaveInstanceState текущего flow позволяют вернуться к билету. После закрытия flow постоянного гостевого доступа нет: письмо либо отдельная регистрация аккаунта/вход. В кабинете все билеты на email | B02 уточнён пользователем 27 октября; гостевой PDF отдельно не задан |
| Q05 | Подтверждение и сброс | После подтверждения email вход вручную. Сброс по коду на указанный email, без предварительного verify email. Ошибки входа «Неверный пароль», «Необходимо подтвердить email» из Android resources. Продление сессии пока неизвестно | B03, принято 27 октября |
| Q06 | Завершение и закрытие регистрации | Регистрацию может закрыть владелец; после startsAt новые заявки недоступны. Finished по действию владельца или заданному endsAt. Начало само не завершает событие | B05, принято 27 октября; timezone/DTO до API |
| Q07 | Отмена билета | Used = по билету уже прошли; отменять нельзя. Active можно отменить, место освобождается один раз. Новая регистрация после отмены допустима при открытой регистрации/местах, со свежим токеном | B08, предложенный вариант принят 27 октября |
| Q08 | Изменение анкеты после ответов | До первой регистрации можно менять вопросы; после первого участника фиксируем вопросы и варианты в MVP. Старые ответы сохраняются с версией формы. Отмена всех регистраций не открывает редактирование заново: факт первой регистрации уже состоялся. Смена названия/места рассматривается отдельно | Принято пользователем после дополнительного объяснения; правило о сохранении блокировки — консервативное техническое следствие, сверить B06 |
| Q09 | Изменение email | Email read-only в MVP; имя/телефон/организацию редактировать. Позднее добавить смену email после серверного протокола подтверждения | Принято для MVP |
| Q10 | Удаление аккаунта | Явный диалог с паролем и перечислением последствий; fake только с demo-данными. Каскад удаления мероприятий, чужих билетов и аудита согласовать с backend до настоящей операции | Рабочий подход принят; серверная семантика остаётся открытой |
| Q11 | Что вводит проверяющий, если камера не читает QR | Разделить QrToken и ManualCode. Предложение backend: отдельный удобный код на билете для ввода, доступный проверяющему только в контексте E. До согласования — отдельный demo manualCode; не объявлять печатный номер токеном | Требуется объяснение пользователю; формат и защита — вопрос backend B11 |
| Q12 | Страница доступна по ссылке; приём регистраций может закрыться | Публичное опубликованное E открыто по ссылке в MVP. Доступность страницы и возможность регистрироваться — отдельные состояния от data layer/API. Флаг закрытия регистрации не скрывает описание и не отменяет выданные билеты автоматически. Description/program optional, редактор этих полей не согласован | Публичный доступ принят; точные статусы и поля — backend B05/B06 |
| Q13 | Неописанные фильтры и metadata билетов | Не добавлять seating/тарифы/универсальные роли; optional metadata показывать при наличии; неописанные действия скрыть | Принято для MVP |
| Q14 | Первый запуск без ссылки | Login + SignUp и подсказка открыть ссылку; host и соглашения через конфигурацию, без каталога | Принято для MVP; реальные URL до API |

## Интеграционные вопросы к backend

Ответы B01–B08: [актуальный реестр от 27 октября](12-backend-answers-2026-10-27.md). [Первоначальный brief](10-backend-brief.md) хранится как история вопросов; B09–B24 пока не отвечены. Ничего разработчику автоматически не отправлено.

- Auth: протокол входа/продления, сроки кодов, технический формат confirm/reset; без гостевого receipt и автосоздания аккаунта.
- Registration: принимаем успех/мест нет/закрыто от сервера; без разработки и тестов его транзакций в Android. Уточняются DTO, версия анкеты и влияние профиля на старые билеты.
- Events: timezone/end time, registration close, deleted/cancelled event, изменение лимита, хранение обложки и programme/description.
- Check-in: token/manual credential, checkpoint, время сервера, atomic first check-in, timeout-after-commit, отзыв grant, минимальные данные результата.
- Dashboard: realtime protocol, freshness, search/pagination, cancelled в счётчиках/экспорте; экспорт XLSX и выдача PDF.
- Email: обязательное письмо с билетом и предпочтения маркетинговых/напоминающих писем; выключение preference не должно молча терять билет — точные категории согласовать.
- Deletion: активные собственные события, чужие регистрации/билеты, исторические check-ins и данные проверившего.
- App Links: контролируемый домен, applicationId, сертификаты debug/release, path contracts и поведение web fallback.

## Как менять решение

Добавить дату, кто подтвердил и короткое объяснение; обновить соответствующие product/navigation/contracts/plan документы и тесты. Исходный JSON не переписывать. Если новое правило меняет модель прав, сначала обновить access matrix и S01, затем экраны.

H0 актуализирован 2026-10-27 по B01–B08, включая замену ранних Q01/Q03/Q04/Q05/Q06. Для каркаса/UI-кита блокирующих ответов нет. B09–B24 пока не отвечены; H1–H4 не проводились. Продуктовые ответы не являются готовой API-спецификацией или проверкой сборки.
