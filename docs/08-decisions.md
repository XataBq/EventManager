## Интеграционные вопросы к backend

**31 октября 2026 — подготовлено предложение API v0.1.0 по прямому запросу пользователя:** [22](22-backend-api-contract.md), [OpenAPI](api/openapi.json) и [отличия текущего Android](api/coverage.md). Это конкретные варианты вместо открытых B09–B24, но не ответы backend и не автоматическое изменение принятых правил. Предложены opaque access/refresh и TTL, протокол повторов, manual code, polling, files и deletion preview. Отдельно требуется сверить гостевую регистрацию на существующий email: новый контракт предлагает выдачу нового билета без login, текущий fake использует RequiresLogin. Каскад удаления Q10 остаётся несогласованным до явного подтверждения. Q11 получает конкретный вариант random QR + отдельный 12-char manual code, пока предложенный. Список оставшихся согласований — §15 нового документа.

Ответы B01–B08: [актуальный реестр от 27 октября](12-backend-answers-2026-10-27.md). [Первоначальный brief](10-backend-brief.md) хранится как история вопросов; B09–B24 пока не отвечены. Ничего разработчику автоматически не отправлено.

- Auth: протокол входа/продления, сроки кодов, технический формат confirm/reset; без гостевого receipt и автосоздания аккаунта.
- Registration: принимаем успех/мест нет/закрыто от сервера; без разработки и тестов его транзакций в Android. Уточняются DTO, версия анкеты и влияние профиля на старые билеты.
- Events: timezone/end time, registration close, deleted/cancelled event, изменение лимита, хранение обложки и programme/description.
- Check-in: token/manual credential, checkpoint, время сервера, atomic first check-in, timeout-after-commit, отзыв grant, минимальные данные результата.
- Dashboard: realtime protocol, freshness, search/pagination, cancelled в счётчиках/экспорте; экспорт XLSX и выдача PDF.
- Email: обязательное письмо с билетом и предпочтения маркетинговых/напоминающих писем; выключение preference не должно молча терять билет — точные категории согласовать.
- Deletion: активные собственные события, чужие регистрации/билеты, исторические check-ins и данные проверившего.
- App Links: контролируемый домен, applicationId, сертификаты debug/release, path contracts и поведение web fallback.

H0 актуализирован 2026-10-27 по B01–B08, включая замену ранних Q01/Q03/Q04/Q05/Q06. Для каркаса/UI-кита блокирующих ответов нет. B09–B24 пока не отвечены; H1 и H2 подтверждены пользователем, H3/H4 ожидаются. Продуктовые ответы не являются готовой API-спецификацией или проверкой сборки.

### ADR-T10-09: online owner projection и явный retry (M04, 17 ноября)

Server MyEvents возвращает typed summary только выбранного tab; nullable draft не превращается в выдуманный published Event. Remote revision/preconditions отсутствуют (null), terminal задаёт серверный read. Editor VM хранит pending create body в памяти, saved state — только marker/local ID/подтверждённый server ID. Adapter хранит ограниченный fingerprint/key/context/retention/cooldown; неизвестный create без тела после process loss не отправляется заново. PATCH включает лишь изменённые поля, null отличается от omission; uncertain PATCH/publish/finish требует read-сверки. Conditional write и durable offline merge не заявлены, остаются M05. RemoteCoverTransfer выполняет один upload с managed source и finally release, затем explicit attach/null detach; preview читает assetId через API origin без bearer на произвольный URL. [Текущие owners/ports/guards/tests](architecture/t10-editor-covers.md).

## ADR-M05 — Room draft slice и ограниченный foreground sync (17 ноября)

Room 2.8.5 / Bundled SQLite 2.7.1, schema1; compiler/KSP фактически скомпилированы с текущим Kotlin2.4.21/KSP2.3.12/AGP9.3.3, без обновления toolchain. Domain DraftStore, data:local хранение, data:remote coordinator, platform managed files. Account auth не восстанавливается из DB. Warm validated account сохраняет local access при временном refresh failure; cold Recovery скрывает retained drafts. Auto401/account switch retain, explicit logout purge + lease fence; файлы noBackup.

Save local-only; explicit sync current draft, без WorkManager/autosubmit/offline publish. Durable create body/key, firstAttempt и 24h unknown gate; unknown PATCH GET-сверка; base/local/remote и осознанный merge. ADR-T10-06 сохраняет гонку GET→PATCH без server condition. Upload без idempotency может оставить orphan asset, exactly-once не обещается. [Действующая спецификация](architecture/t10-room-drafts.md).

Поздняя команда пользователя сократила проверки до remote compile, без сценарных прогонов/lint/demo/APK. Это не техническая или человеческая приёмка M05. M04 review принят пользователем при запуске M05, повторного авторского ревью нет.

## M09: внешние условия и предел приёмки, 17 ноября 2026
