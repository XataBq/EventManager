# M02: публичное мероприятие, анкета и schema 6

Реализация поверх M01, техническое принятие требует отдельного ревью. [Критерии M02 и ADR](../34-api-migration-plan.md), [evidence](../validation/t10-m02-implementation.md). M03–M09 не реализованы: remote submit/tickets/editor/grants/attendance/files возвращают FeatureUnavailable. Ниже фактический срез, не обещание готовности всего API.

## Вход и владение

`PublicEventReference.Slug(EventSlug)` адресует public GET `/events/{slug}`; `Internal(EventId)` — явно локальный/demo путь, который remote не отправляет на сервер. Внутренние eventId/slug не конвертируются друг в друга. Slug до 300 Unicode code points, один URL path segment; literal percent не декодируется повторно. [PublicEventLinkParser](../../core/platform/src/main/kotlin/ru/eventpass/core/platform/PublicEventLinkParser.kt) разрешает только HTTPS eventpass.dikanskii.ru/staging.eventpass.dikanskii.ru, `/e/{slug}`, без userinfo/query/fragment/другого порта/дополнительного сегмента. Dot segments запрещены. Это явная вставка ссылки, не App Links.

Configuration detach сохраняет незавершённую форму той же VM; обычный dispose/уход очищает её, нового process restore answers нет. EventKey/ReturnDestination сохраняют отдельно publicSlug и internal eventId, безопасный flowId; raw URI/bearer не сохраняются. Common EventRoute получает reference и VM своей entry; visible + RESUMED bind/read/refresh, stopReading отменяет subscription/read и увеличивает owner. PrivateScope по M01 удаляет приватные owners при смене сессии. Remote host защищает content safeDrawing/IME insets; back stack/public slug живут в NavEntry saveable registry. [Текущая навигация](../03-navigation.md).

## Remote read

[RemoteEventRepository](../../data/remote/src/main/kotlin/ru/eventpass/data/remote/RemoteEventRepository.kt) реализует только observe/refresh public E за EventRepository. Entry по slug содержит transient stamped result, число подписчиков и Mutex. Observe запускает GET при необходимости; параллельный pull не ставит вторую загрузку. Отписка последнего клиента удаляет cache; lifecycle не заменяется polling. StateFlow не означает server push.

Контекст захватывает проверенный session snapshot/epoch и data-local bearer/profile у RemoteAuthRepository. До запроса, после HTTP и на consumer edge сверяется контекст: queued ответ старого actor не возвращает viewer/contact/ticket. При смене сессии прежний content может остаться только в publicOnly проекции без private полей, затем выполняется актуальный GET. 401 текущего bearer очищает session/token; late 401 старой сессии не выталкивает новый login. 403 отличается от 401. Errors: NotFound / Network / Timeout / Forbidden / ServerUnavailable / Protocol; malformed published response не достраивается фиктивными датами/owner/capacity. AuthHttp запрещает redirect/retry mutation и выход URL за API origin/path; auth response limit 1 MiB остаётся отдельно от public form response ≤32 MiB, включая escaped Unicode.

Map использует server status/counts/viewer: PUBLISHED/LIVE/FINISHED, положительный capacity, registered/checked counts, starts/ends/effectiveEnds/finishedAt. Effective end проверяется как endsAt либо start+4h, но client Clock не превращает серверный LIVE в локальный FINISHED. Paid/free — metadata, оплаты нет. Owner/volunteer/own ticket независимы, private capabilities допустимы только при проверенной сессии, unverified email не закрывает вход. Local EventAccessPolicy применяется fake, не подменяет server viewer. Локальная timezone отображения Europe/Moscow не выдаётся за поле API.

Remote Event.revision/localSchemaRevision = null; нет server formVersion/If-Match. Section IDs/option values/question IDs сохраняются. Nullable incomplete draft обрабатывается редакторской моделью EventFields; public endpoint с draft/null required published полями даёт Protocol. Cover descriptor/URL сохраняются как metadata; remote upload/download следующих этапов здесь не имитируется.

## Анкета и команды

TextFormat TEXT/TEXTAREA/EMAIL/TEL/NUMBER/DATE, ChoiceFormat CHOICE/SELECT, MultipleChoice и Checkbox покрывают 10 wire типов. Answers — Text/SingleChoice/MultipleChoice/Checkbox, для M03 соответствуют string/string[]/boolean. Help/placeholder/hint сохраняются domain/editor/fake/codec, UI использует существующий design system. Unknown type становится Unsupported и блокирует validator/submit, не Text. Required checkbox=true, optional=false; варианты опубликованного choice/select/multiple ≥2 с уникальными values. Лимиты считаются code points: metadata 300, description 20000, answer text 4000; questions/options/sections ≤50.

EventViewModel при изменении questions сопоставляет stable ID/kind и values options: совместимые ответы остаются, несовместимые исключаются с объяснением StaleForm. Consent/contact не стираются просто из-за новой схемы. Command generation меняется только при уходе/смене event identity/actor/denial, не при rename/help/type refresh: уже принятый submit не теряет билет от локального schema change. Поколения result/finally по-прежнему защищают следующую отправку; отмена не обещает rollback сервера. При изменении actor contact-поля/ответы очищаются; forbidden/notfound тоже очищают форму. Server ownTicketId открывается без ожидания ещё недоступного M03 ticket-порта.

Fake localSchemaRevision/revision — локальные preconditions и publication receipt; remote не получает этих полей. Вопросы demo теперь редактируются после регистрации; новые регистрации сохраняют questionSnapshot, старые labels не достраиваются из новой схемы. Legacy без исторического snapshot экспортирует безопасный ID/пустые неизвестные labels. CloseRegistration удалён из порта/UI; LIVE регистрация допустима, default effective end — 4h, published capacity >0. Остальной guest autoaccount/idempotency/EVT/server files/resend cleanup принадлежит M03+; прежний demo guest пока выдаёт snapshot без создания аккаунта.

## Хранение и миграции

ProductSnapshotCodec writer v6: length-prefixed bounded UTF-8 (строка ≤200000 bytes), record/field bounds, общий snapshot ≤32 MiB. Этот предел вмещает предельную Unicode-форму вместе с историческим questionSnapshot; AtomicFile reader также ограничен до чтения неограниченного файла. Session/outbox/faults/refresh не persist. Все fake writers используют один codec/Mutex/IO и сохраняют соседние records, QR/manual/first-check proofs.

Reader v1/EPA2 auth-only восстанавливает auth + product seed. V2–v5 читаются отдельным LegacyProductSnapshotCodec с прежним 8 MiB bound. Совместимые E получают детерминированный demo slug и local section IDs, не server IDs; credentials/status/history/profile сохраняются, известная историческая схема не выдумывается. Целевой v6 round-trip сохраняет explicit IDs/nullable local versions/all question metadata/answers/price/remote cover descriptors.

Известные корректно прочитанные, но несовместимые legacy E (cancelled, неположительный/null published capacity, single-option published choice, новые storage bounds) требуют явного reset. До этого Unknown/StorageUnavailable, файл нетронут; reset сначала атомарно архивирует оригинал `demo-legacy-before-schema6.bin`, только затем пишет seed6. Ошибка backup не даёт reset. Truncated/corrupt/unknown version/trailing/oversized данные не объявляются известной несовместимостью и не перезаписываются автоматически. Downward migration не поддерживается.

## Локальная актуальность билета

Исправление P2 из ревью M02: Ticket.isCurrent для локальной модели использует Event.statusAt(now), поэтому default start+4h, explicit end и finishedAt согласованы с регистрацией/scanner. Активный QR допустим только для ACTIVE ticket при PUBLISHED/LIVE; тест RegistrationRulesTest.ticketExpiryMatchesDefaultExplicitAndManualEventEnd. [Результаты и границы исправления](../validation/t10-m02-fix-ticket-expiry.md); повторное ревью ожидается. Это не реализация server TicketEvent/policy будущего M03.
